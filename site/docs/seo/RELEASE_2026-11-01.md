# SEO and contact flow release — 2026-11-01

## Implemented changes (verified in source)

- FormSubmit navigation previously took people to a third-party "Almost There" CAPTCHA page. `ProfessionalContactForm.astro` now posts to the documented `/ajax/` JSON endpoint, reports success **only after** `success: true` or `success: "true"`, handles provider rejection/network timeout with a recoverable error, preserves user input and offers the existing direct-email link.
- The form includes `_captcha=false`, a hidden honeypot, required-field validation, a 15-second request timeout, and a disabled state preventing double submissions.
- Browser regression coverage verifies inline success, provider rejection, the preserved inputs and no navigation to the third-party page. **Live email delivery** must still be confirmed with the owner after deployment; source/CI tests use mocked provider responses.
- FormSubmit warns that disabling CAPTCHA can increase spam risk and invoke provider limits. For stronger rate limiting and anti-spam, a future backend with server-verified Turnstile is preferable; do not claim the honeypot alone is server-side protection.

## Sitewide and editorial technical SEO

- `BaseLayout.astro` now distinguishes authored article pages from topic archive pages when selecting Open Graph type, adds social image dimensions and alt metadata, and emits article publication/modification metadata only for articles.
- `blog/[slug].astro` provides article-level `publishedAt`/`modifiedAt`, machine-readable `<time>` elements, citations directly from the same editorial source list visible to readers, `articleSection` and WebSite graph linking.
- All 17 blog articles inherit these improvements through the single shared template. Topic archives and blog archive continue to use canonical page metadata and the previously implemented breadcrumbs.
- The homepage portrait uses the responsive WebP variants that the existing Sharp build already generates; the LCP preload now describes the same responsive source set instead of separately preloading the larger JPEG.
- The built-site verifier checks all generated indexable pages for titles, descriptions, canonical URLs, one H1, JSON-LD syntax, image dimensions/alt, crawlable local links, sitemap inclusion, social image dimensions, and article-specific dates and type.
